01 Robocor · Lead Software Engineer · 2024 to present

The control platform behind a security robot on patrol today

Robocor builds autonomous security robots. I designed and wrote Robocor 2.0, the software that drives them: one Flutter codebase for the operator app on iOS, Android, macOS, Windows, Linux and the web, a perception and navigation stack on NVIDIA Jetson, and a cloud backend for fleets and telemetry. The Guardian robot now patrols a live customer site, Nimnicht Chevrolet, on this stack.

  • Wrote the full chain from the firmware serial protocol and motor watchdog up to the cloud backend and operator UI.
  • Built the on-device perception pipeline: YOLO26 and YOLO-World detection, metric depth and segmentation models running through ONNX Runtime, TFLite and TensorRT on Jetson, fed by a ZED stereo camera. I maintain the Flutter ONNX Runtime plugin it runs on.
  • GNSS/RTK path following and offline mapping and navigation that keep working when the network does not.
  • An OpenAI GPT-4o operator agent with realtime voice, so staff can talk to the robot in plain language.
  • Created corBench, a WebGPU and Rapier physics test bench where virtual sensor boards drive the real parsers unchanged. 580+ recorded runs to reproduce field failures and validate navigation changes before they reach hardware.
  • Own the infrastructure: Supabase (Postgres, auth, storage), multi-tenant workers on Fly.io, Docker, CI and release pipelines for Windows, macOS and Jetson.

02 VEERA Medical · Software Developer III · 2021 to present

MedXR (Recovr360): physical therapy on a Meta Quest, supervised from a browser

A white-label physical-therapy platform. The patient wears a Quest headset; the practitioner watches, adjusts and records from any browser. I built and launched it alone, backend to headset, and it is now used in more than 15 clinics. We demonstrated it live at ACRM 2023 with a practicing clinician running the session wirelessly on stage.

  • Node and TypeScript real-time backend: server-authoritative Colyseus rooms with a strict session lifecycle, device-code pairing of headset and practitioner, Express APIs.
  • Svelte and Three.js WebXR client, a Unity scene exporter and a native Quest client that share one session model.
  • Migrated the whole platform from Fly.io to AWS ECS Fargate behind an ALB, with Cloudflare in front and Auth0 login rolled out behind feature flags.
  • Accessible patient input: Xbox Adaptive Controller, wheelchair joystick adapters and standard gamepads.
  • Started as the company's first developer in 2021 and wrote the original application in C#, Unity and ASP.NET Core on the Reach Cloud codebase.

How I work

Four rules I work by

1

Ship the whole thing

A feature is not done when the API returns 200. It is done when the installer runs, the operator understands the screen, and the log tells you why it broke at 2 AM. I take responsibility for all of it.

2

Simulate before you bolt it on

On Robocor I built a physics test bench because a bad navigation change costs a day of hardware time and a bruised robot. A failing test in simulation costs ten seconds. Cheap failures first.

3

Boring infrastructure, interesting product

Postgres, Docker, a managed host and CI you can read in one sitting. The novelty budget goes to the thing the customer sees, not the deploy script.

4

Use AI agents like a lead uses a team

I run coding agents daily and built my own tooling to manage them. They are fast and they are wrong in predictable ways. The job is architecture, review and judgment. That is where I spend my time.
